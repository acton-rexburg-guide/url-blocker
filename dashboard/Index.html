    Q&A
    

          
    
            How do rules interact with each other and with Google Admin?
            
    
              
    
                
    Admin console URL blocking and this filter
    
                
    
                  
    They are two separate filters, and neither can override the other. A page opens only if both allow it, so the stricter one always wins.
    
                
    
                
    
                  
    
                    
    Admin console URL blockingThis filterResult
    
                    
                      
    AllowedBlockedBlocked by this filter
    
                      
    BlockedAllowedBlocked by Chrome
    
                      
    Allowed or not listedAllowedOpens
    
                        
                  
    
                
    
                
    
                  
    Allowing a site here can't undo a block in the Admin console, and an Admin console allow can't undo a block here. To avoid confusion, move your lists here with Import Admin console URL lists and then clear them in the Admin console.
    
                
    
              
    

              
    
                
    Organizational units and groups
    
                
    
                  
    This works the same way for this filter and for Admin console URL blocking. Each user gets the settings of exactly one OU or group:
    
                  
      
                    
    1. A group beats an OU. If any of the user's groups has its own settings, the group's settings are used instead of the OU's.
      2. 
                    
    2. Several groups: the group ranked highest wins. Set the order in the Admin console under Devices → Chrome → Apps & extensions → Users & browsers → Groups.
      3. 
                    
    3. Sub-OUs: the closest OU with its own settings wins. A sub-OU uses its parent's settings until you save settings on it.
      4. 
                  
    
                  
    Settings are never merged. The winner's mode, lists and schedules all apply, and everything else is ignored. For example, if a student's OU uses allowlist mode and one of their groups uses blocklist mode, the group's blocklist applies and the OU's allowlist doesn't apply at all.
    
                
    
              
    

              
    
                
    Allowed vs. blocked within one set of settings
    
                
    
                  
    The first rule below that matches a page decides it:
    
                  
      
                    
    1. Google sign-in and account pages, if Never block Google sign-in and account pages is on
      2. 
                    
    2. Approved sources, and temporary allows
      3. 
                    
    3. Allowed sites
      4. 
                    
    4. Blocked sites
      5. 
                    
    5. In allowlist mode, everything else is blocked. In blocklist mode, everything else is allowed.
      6. 
                  
    
                  
    Schedules that are on add their sites to the allowed and blocked lists. If several schedules change the mode at the same time, the one lowest in the list wins.
    
                
    
              
    

              
    
                
    Difference from the Admin console: allowed always beats blocked
    
                
    
                  
    Admin console: the most specific entry wins. With youtube.com allowed and youtube.com/shorts blocked, Shorts is blocked.
    
                  
    This filter: an allowed entry wins no matter how specific the blocked entry is. With the same two entries, Shorts stays open.
    
                  
    Here, only the opposite pattern works: block the whole site and allow a part of it, for example block youtube.com and allow youtube.com/edu. After importing Admin console lists, check for blocked entries that sit inside allowed sites.
    
                
    
              
    
            
    
          
    

          
    
            A site isn't blocked, but chrome://policy shows the right settings. Why?
            
    
              
    Settings arriving on the device only means Chrome has them. Check these, in order:
    
              
      
                
    1. Is the site allowed somewhere? Allowed always beats blocked. Look in Allowed sites, in the Also allow list of every schedule that's on at the same time, and in Approved sources. A domain covers its subdomains, so allowing google.com also allows sites.google.com.
      2. 
                
    2. Was the page opened from an approved source, or does someone have a Temporarily allow in effect? Both let pages through on purpose.
      3. 
                
    3. Was the tab already open? Pages are checked as they load. A tab that was open before the rule took effect stays open until it reloads or goes to another page.
      4. 
                
    4. Is the schedule actually on? See the next question.
      5. 
                
    5. Is the extension running? Click its toolbar icon on the device. It should say Settings from: Google Admin console and show the mode and schedules you expect.
      6. 
              
    
            
    
          
    

          
    
            My schedule doesn't turn on (or off) at the right time.
            
    
              
      
                
    • Check AM and PM. Open the schedule and make sure the start and end show the times you mean, such as 2:00 pm rather than 2:00 am.
      • 
                
    • Check the days. An end time earlier than the start runs past midnight, and it belongs to the day it starts on. A Friday 10:00 pm–6:00 am schedule runs into Saturday morning.
      • 
                
    • Check the time zone. If Time zone is blank, each device uses its own clock, which may be wrong or set to another zone. Set your school's zone, such as America/Denver.
      • 
                
    • Same start and end means all day on the chosen days.
      • 
                
    • On the device, the extension's popup lists the schedules that are on right now.
      • 
              
    
            
    
          
    

          
    
            A site is blocked, but it's on my allowed list.
            
    
              
      
                
    • Admin console URL blocking is a separate filter. If the site is blocked there (Devices → Chrome → Settings → URL blocking), Chrome shows its own block page and nothing here can undo it.
      • 
                
    • A different OU or group may apply. Settings are never merged: a group's settings replace the OU's. Use Check a user to see which settings that person actually gets.
      • 
                
    • A path entry only covers that path. youtube.com/edu doesn't allow the YouTube home page.
      • 
                
    • The page may use other sites. In allowlist mode, a page that sends people to another domain (for example a sign-in page on a different site) needs that domain allowed too. With Also filter embedded frames on, embedded videos and widgets need their sites allowed as well.
      • 
              
    
            
    
          
    

          
    
            I saved changes, but a device still has the old settings.
            
    
              
      
                
    • Devices pick up changes within a few minutes. To apply them at once, open chrome://policy on the device and click Reload policies.
      • 
                
    • Make sure you saved to the OU or group that person is in. Check a user shows which one wins.
      • 
                
    • The person must be signed in to Chrome with their school account. The settings follow the account, not the device.
      • 
              
    
            
    
          
    

          
    
            The extension's popup says "Not configured" or the extension is missing.
            
    
              
      
                
    • Missing from chrome://extensions: the extension isn't force-installed for that person. Run Check a user. It flags a missing install.
      • 
                
    • "Not configured": no settings reach that person. Save settings on their OU, a parent OU, or one of their groups.
      • 
                
    • "Waiting for policy to load": Chrome hasn't finished loading policy. Wait a minute, or click Reload policies on chrome://policy.
      • 
                
    • Check the Extension ID under Setup. Settings saved for a different ID never reach the extension.
      • 
              
    
            
    
          
    

          
    
            The Temporarily allow button doesn't appear on the blocked page.
            
    
              
    The button only appears once an admin password is set under Setup → Temporary allow. If a password is set and the button is still missing, setting it may have failed for that person's OU or group (the message after setting it lists any it couldn't update). Set the password again, then click Reload policies on chrome://policy on the device.
    
            
    
          
    

          
    
            How do I get help with a problem on one device?
            
    
              
      
                
    1. Run Check a user with that person's email and click Copy report.
      2. 
                
    2. On their device, click the extension's toolbar icon, then Copy diagnostics. It shows the device's time and time zone, the settings the extension received, and the rules it has in place.
      3. 
                
    3. Share both, along with the site and the time it happened.
      4.
